# 跨区域保供调拨

区域底线、保留池、调拨轮次与运输回执的领域服务。事件日志（SQLite）是唯一事实
来源，所有状态由事件重放得到——进程随时重启，未决轮次继续，账目随时对平。

## 领域规则

- **分轮决策**（`supply/allocation.py`，纯函数可单测）
  1. 底线轮：先保每个区域的民生底线，**在途补给**冲减缺口，按**损耗率**把净到货
     量换算为发运量；货源紧张时**运输时效慢**的区域先拿货，远途区域不会被拿空。
  2. 合同轮：按客户**合同保量**缺口分配，缺口大者优先。
  3. 份额轮：余量按**历史兑现份额**加权，受申报需求封顶后再分配余量。
- **保留池**：常规轮次不参与分配；仅常规轮次结束后的紧急需求可动用。
- **授权挤占**：保留池不足时，紧急需求须带授权才能挤占**尚未确认/发运**的额度；
  先挤合同/份额轮额度（补偿层级 1），触及民生底线份额为层级 0（最高补偿优先级），
  被挤占方自动生成可追踪补偿单（`comp-*`），后续补给入池后按
  `tier, priority` 严格顺序兑现。已确认/发运/到达额度不可挤占。
- **回执生命周期**：确认 → 装运 → 到达，必须按序；迟到回执按**真实发生时间**
  登记，但状态投影只进不退；同一 `request_id` 重试直接返回首次结果，**不重复
  扣配额、不重复挤占**。
- **模拟与批准链**：供应缩减先产出隔离的模拟版本（不产生调拨单、不动保留池），
  指挥员确认后，正式版本必须收齐按序签批的批准链才能发布；同轮旧版本作废。
- **对平**（`reconcile`）：现存调拨有效量 + 保留池余额 + 常规轮余量 = 总货源，
  并逐区域给出底线（在途 + 已确认净到货）核对。

## 代码结构

- `domain/contract.json`：实体、状态、事件类型（按 v1/v2 追加版本）。
- `supply/allocation.py`：三轮分配与紧急挤占的纯函数决策。
- `supply/store.py`：事件表（只追加）+ 投影表，启动时清空投影重放重建。
- `supply/service.py`：命令处理、幂等、批准链、回执、紧急挤占、补偿、对平。
- `supply/errors.py`：领域错误（`AuthorizationRequired` 等）。
- `examples/demo.py`：四区域加急上午的端到端演示。
- `tools/validate_contract.py`：合同与样例事件的离线一致性校验。

## 构建 / 测试 / 校验 / 演示

```bash
python3 -m compileall -q .
python3 -m unittest discover -s tests -v
python3 tools/validate_contract.py
python3 examples/demo.py
```

所有命令均在项目根目录执行，仅依赖 Python 3.11+ 标准库，不需要启动额外服务。
生产使用时把 `Store(":memory:")` 换成文件路径（如 `data/supply.db`）即可持久化。
